# Walkthrough — Slug Deep Link No-Expand & Anti-Flicker Hardening

We audited the deep link slug feature (`#raid-N` in the URL → scroll to that raid card + faint glow highlight) against the records in `doc/prompts/` and found three regressions that were reintroduced after the original 18.3–18.6 flicker-fix sessions. All three are now resolved.

---

## 🔍 What Was Wrong

### 1. Cards Were Being Force-Expanded on Deep Link
Both `scrollToRaid()` and `renderRaids()` contained code that opened the `<details>` element whenever a slug URL was used:

- **`scrollToRaid()`** explicitly did `card.open = true` before scrolling.
- **`renderRaids()`** (initial render path) evaluated `isTargetedRaid` and ORed it into `card.open`.

The user's requirement is: slugs **only** scroll and glow. The card's collapsed/expanded state should be independent and untouched.

### 2. `transition: none !important` Was Missing from `.raid-card.highlighted`
The base `.raid-card` rule carries a 0.3s CSS `transition` on `transform`, `border-color`, and `box-shadow`. When the `@keyframes highlightPulse` animation begins animating those same properties, the browser's transition engine and animation engine compete, causing a brief subpixel jitter on the first few frames.

This `transition: none !important` override was first added in session **18.3** (Flicker Fix), but had been dropped from the current code.

### 3. GPU Compositing Hints Were Also Missing
`will-change: box-shadow` and `backface-visibility: hidden` were also first added in 18.3 and subsequently dropped. Without them, the browser may rasterize the card's glow during the main thread paint cycle rather than on the compositor thread, increasing the risk of jank during page load when the main thread is busy.

## 🛠️ Changes Made

### [`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js) — `scrollToRaid()`: removed force-open
```js
// Removed these 4 lines entirely:
if (card.tagName.toLowerCase() === 'details' && !card.open) {
    isProgrammaticScrollOpening = true;
    card.open = true;
    setTimeout(() => { isProgrammaticScrollOpening = false; }, 80);
}
```
The card now simply `scrollIntoView()` and gets `.highlighted` applied — open state untouched.

### [`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js) — `renderRaids()`: removed `isTargetedRaid` auto-open
```js
// Before:
if (hasRenderedBefore) {
    card.open = openCardIds.has(card.id);
} else {
    const isTargetedRaid = ...;
    card.open = openCardIds.has(card.id) || isTargetedRaid;
}

// After (simplified):
card.open = openCardIds.has(card.id);
```

### [`style.css`](file:///d:/GitHub/[oU1TS]/events/style.css) — `.raid-card.highlighted`: restored anti-flicker CSS
```css
.raid-card.highlighted {
    transition: none !important;          /* ← restored: stops transition competing with keyframe */
    animation: highlightPulse 2.1s cubic-bezier(0.22, 1, 0.36, 1) forwards;
    z-index: 10;
    border-color: var(--accent) !important;
    will-change: box-shadow;              /* ← restored: GPU compositing hint */
    backface-visibility: hidden;          /* ← restored: promotes to compositor layer */
    -webkit-backface-visibility: hidden;
}
```
