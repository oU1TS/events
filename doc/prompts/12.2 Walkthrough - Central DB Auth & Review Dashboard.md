# Walkthrough: 12. Central Database Authentication, Event Update Proposals & Review Dashboard

## Overview of Implemented Features

1. **Central Supabase Integration**:
   - `events` is now connected to the central database of `ou1ts.github.io` via `env-config.js` and `@supabase/supabase-js@2`.
   - Shared authentication credentials allow members to register, log in, recover passwords, and synchronize profile details (Name, Student ID, Department, Blood Group).

2. **Adaptive Auth Controls**:
   - **Desktop**: A sleek glassmorphic floating action button (`#desktop-auth-btn`) positioned at `bottom: 2rem; left: 5.5rem;`. Toggles between "Login" and "Dashboard" with member avatar.
   - **Mobile**: A full-width navigation item (`#mobile-auth-btn`) anchored at the very bottom of the mobile sidebar drawer (`#main-nav`).
   - **Logout**: Placed securely inside the Guild Dashboard window.

3. **Event Proposals & In-Card "Suggest Edit"**:
   - Logged-in users can propose new raids via the Dashboard or click the "✏️ Edit" button injected next to the status badge on any card on `#raids`.
   - Opens `#event-form-modal` pre-filled with the selected raid's details and dynamic sub-events repeater.
   - Submissions are sent to `public.event_submissions` with `pending` status.

4. **Staff Review Dashboard (Admin & Mods)**:
   - Gated to `admin` and `mod` roles.
   - Tabbed filtering for Pending, Approved, and Rejected proposals.
   - Visual side-by-side diff table comparing the active card parameters with the proposed changes.
   - One-click "Approve Proposal" (applies live in-memory updates) and "Reject" (with feedback notes).
   - Export tools: "Download raids.json" triggers a browser download of the updated JSON dataset, and "Copy JSON" copies the merged JSON to the clipboard.

5. **Moderator Management (Admin Only)**:
   - Gated strictly to `admin` role.
   - Opens `#mod-management-modal` displaying registered community profiles from `public.profiles`.
   - Search bar filters users in real time.
   - Admins can appoint or revoke Moderator status (`event_roles`).

6. **Database Schema Setup Script**:
   - `doc/db/event_raids_schema.sql` provides the complete SQL migration ready to run in the Supabase SQL editor.
   - Includes instructions for assigning initial Admin privileges via direct SQL insertion.

## Verification & Testing Guide

1. **Local Test**:
   - Open `index.html` in browser.
   - Verify that the floating button appears on desktop with "Login" text and hover gold glow.
   - Open mobile drawer (`<= 768px`) and verify the "Login" button sits at the very bottom of the sidebar.
2. **Authentication Flow**:
   - Click "Login" to open the Auth modal.
   - Switch between "Login", "Register", and "Forgot Password" tabs.
   - Log in with valid credentials. Verify that desktop and mobile buttons switch to "Dashboard".
   - Open the Dashboard: check profile details, role badge (`Admin`, `Mod`, or `Member`), recent submissions list, and Log Out button.
3. **Event Proposal**:
   - Navigate to `#raids`: notice the "✏️ Edit" button beside each card's status badge.
   - Click "✏️ Edit" on any raid card: verify that `#event-form-modal` opens pre-filled with the event's title, dates, venue, fee, sub-events, and links.
4. **Review & Moderation**:
   - With an Admin/Mod account, open Dashboard -> "Review Submissions".
   - Verify side-by-side diffs, Approve/Reject buttons, and the "Download raids.json" button.
   - With an Admin account, open Dashboard -> "Manage Moderators" to appoint or revoke mods.
