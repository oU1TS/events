# Implementation Plan - Raid Card Highlight Animation Flicker Fix

## Overview
When accessing a raid card directly via its deep link (e.g. `index.html#raid-1`), the target card opens and starts its 3.5s breathing highlight pulse animation (`highlightPulse`). However, during initial page load, a visible flicker or micro-stutter occurs midway through the glow animation.

### Root Causes
1. **False-Positive Database Change Re-Renders**:
   `applyApprovedSubmissionsToDataset()` in `app.js` unconditionally flagged `hasChanges = true` for every approved record returned from Supabase, even when the data matched `pastRaidsData` and cached submissions 100%. This caused `syncApprovedSubmissionsFromDatabase()` to execute `filterAndRenderRaids()` ~200ms–500ms into the initial page load, clearing `raidsContainer.innerHTML = ''` and destroying the DOM element while the animation was playing, then restarting it from 0%.
2. **Double Animation Trigger in `scrollToRaid()`**:
   When `scrollToRaid()` is called while a card is already highlighted (e.g. from rapid hash/render events), it unconditionally removed `.highlighted`, forced a reflow (`void card.offsetWidth`), and re-added the class, resetting the animation abruptly mid-glow.
3. **Redundant Force-Fresh Reload in `initCacheAndNotifications()`**:
   If the remote tracker triggered a fresh reload (`loadPastRaids({ forceFresh: true })`), it bypassed caching and rebuilt the DOM without verifying if `raids.json` contents actually differed from what was already loaded.
4. **CSS Transition vs Keyframe Animation Conflict**:
   `.raid-card` defines a 0.3s CSS `transition` on `transform`, `border-color`, and `box-shadow`. When `.highlighted` applies `@keyframes highlightPulse` on the exact same properties, the browser transition engine and animation engine compete during initial frames, causing a subpixel paint flicker.

---

## Proposed Changes

### 1. `style.css`
Update `.raid-card.highlighted`:
- Add `transition: none !important;` to disable competing property transitions during animation.
- Add `will-change: transform, box-shadow;` and `backface-visibility: hidden;` to composite the card onto its own GPU layer, preventing subpixel jitter.

### 2. `app.js`
- **Data Change Detection in `applyApprovedSubmissionsToDataset`**:
  Compare existing objects against merged objects (`JSON.stringify(merged) !== JSON.stringify(existing)`). Only set `hasChanges = true` if there are real differences.
- **Idempotent Highlight Handling in `scrollToRaid`**:
  If the target card already possesses `.highlighted` and an active highlight timer is running, preserve the existing animation instead of forcing reflow and restarting frame 0.
  Only set `card.open = true` if `!card.open`.
- **Deduplication in `loadPastRaids`**:
  When `options.forceFresh` is supplied, check if the fetched JSON matches existing `pastRaidsData`. If data is unchanged, skip wiping and re-rendering DOM elements.

### 3. Documentation & Verification
- Explain the browser console logs (`Permissions-Policy` header warnings and `ERR_BLOCKED_BY_CLIENT` from ad-blockers blocking OneSignal).
- Update `documentation.md` (v1.17.1), `learning.md`, and `README.md`.
