### Thinking Process

1. **Analyze Existing Proposal Architecture & Database Mapping**:
   - Inspected `index.html`, `style.css`, and `app.js` to understand `#event-form-modal` and its submission pipeline.
   - Identified that Supabase `event_submissions` stores the raid payload directly in `data` (matching `raids.json` structure), which aligns with Gemini-generated JSON blocks.
2. **Design Mode Switcher & Monospace JSON Editor**:
   - Designed a modern segmented control (`#mode-pill-form` and `#mode-pill-json`) in `#event-form-modal`.
   - Built `#proposal-json-view` containing a monospace editor (`#form-json-raw`), a usage guide card, and quick action tools:
     - **Insert Starter Template**: Automatically computes and fills the next `Raid_Num`.
     - **Format / Beautify**: Prettifies JSON with 2-space indentation and validates syntax.
     - **Sync to Form Fields**: Parses JSON and populates standard form inputs.
   - Built a dynamic syntax badge (`#json-syntax-indicator`) reporting real-time validity (`✓ Valid JSON: Raid #...` vs `⚠ Syntax Error`).
3. **Implement Bidirectional Synchronization & Direct Submission**:
   - Added two-way synchronization: serializing form inputs into JSON when toggling to JSON mode, and populating form fields from JSON when toggling back to Form mode.
   - Updated the form submission handler to validate JSON, support both single-object and array payloads, auto-detect `update` vs `new` proposals, bypass hidden input validation, and push to `event_submissions`.
4. **Implement Download raids.json in `#raids` Section**:
   - Added `#download-raids-json-section-btn` into `.calendar-btn-container` alongside Calendar, Filter, and Past Raids controls.
   - Extracted a unified `downloadRaidsJsonFile()` handler servicing both the roadmap section and the Review Dashboard modal.
