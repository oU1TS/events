# Walkthrough - Accessibility Hardening, Copy Button Visibility & Dropdown Restriction Fix

This walkthrough details the systematic resolution of browser DevTools console errors, Issues tab violations, and card dropdown interaction restrictions:
1. **Interactive element inside of a `<summary>` element (13 elements)**: Eliminated all disallowed descendants from `<summary>` elements according to W3C HTML5 & WCAG accessibility standards.
2. **Copy Button Visibility (`.copy-raid-link-btn`)**: Fixed the copy link button disappearing when cards were collapsed. By introducing a `.raid-card-wrapper` (`position: relative; overflow: visible;`), `.copy-raid-link-btn` is appended to the wrapper outside `<details>`, ensuring it remains permanently visible on top of the card in both collapsed and expanded states while never violating `<summary>` phrasing content rules.
3. **Highlight Animation Restricting Dropdown Features**: Removed the artificial DOM lock (`pendingReRender`) inside `filterAndRenderRaids`. User category dropdown filters and card accordion toggles now respond instantly without being queued or blocked during the 2.1s pulse animation. Also added state retention for inner Details dropdowns (`details.details-dropdown[open]`) and Schedule dropdowns (`details.schedule-dropdown[open]`).
4. **Form Field Label Compliance (2 resources)**: Added `.visually-hidden` `<label>` elements and explicit `aria-label` attributes to `#mod-user-search-input` in `index.html` and `#search-input` in `render.html`, plus dynamic repeater fields in `app.js`.
5. **Permissions-Policy Header & OneSignal `net::ERR_BLOCKED_BY_CLIENT`**: Explained the origin of server-level GitHub Pages Privacy Sandbox headers and introduced defensive guards around OneSignal SDK initialization.

## Changes Implemented

### 1. Raid Card Wrapper & Permanent Copy Button Visibility

* **Problem**: In the previous iteration, `.copy-raid-link-btn` was moved to `card.appendChild(copyBtn)` to remove it from `<summary>`. Because `card` is a `<details>` element, HTML5 hides all non-`<summary>` children whenever `<details>` is collapsed (`open` attribute absent). As a result, the copy button disappeared on collapsed cards and only appeared when expanded.
* **Resolution**:
  - Wrapped each raid card in a `.raid-card-wrapper` div with `position: relative; overflow: visible;`.
  - Appended `card` and `copyBtn` as direct sibling children of `cardWrapper`.
  - Styled `.copy-raid-link-btn` with `position: absolute; top: -10px; right: -10px; z-index: 20;`, ensuring it floats neatly on top of the card header in both collapsed and expanded states without being nested inside `<summary>`.

```html
<!-- Final Clean DOM Structure -->
<div class="raid-card-wrapper">
    <details class="raid-card parent-raid-card" id="raid-card-22">
        <summary class="parent-raid-summary">
            <!-- Valid phrasing content only: metaDiv, titleRow, typeTag, cornerBadge (span) -->
        </summary>
        <div class="parent-raid-body">
            <!-- Description, Details dropdown, Schedule items, and content copy button -->
        </div>
    </details>
    <button type="button" class="copy-raid-link-btn" title="Copy link to this raid" aria-label="Copy link to this raid">
        <!-- Always visible copy link icon button -->
    </button>
</div>
```

### 2. Elimination of Dropdown Restrictions During Highlight Animation

* **Problem**: `filterAndRenderRaids` previously locked DOM mutations while any card had `.highlighted` (`pendingReRender = () => filterAndRenderRaids({ forceImmediate: true })`).
  - When the user interacted with the Event Type dropdown filter, the action was blocked until the animation ended.
  - When the user clicked to collapse the card, `stopHighlightAnimation` fired `pendingReRender()`, which called `renderRaids()`. Since the card was still technically open when `renderRaids` ran, `openCardIds` captured it as open and re-opened it, reverting the user's collapse.
  - When the animation ended, `pendingReRender()` wiped `raidsContainer.innerHTML = ''`, which snapped any open inner Details dropdown shut.
* **Resolution**:
  - Removed `pendingReRender` and the lock inside `filterAndRenderRaids`. Category filters and Past Raids toggles now execute immediately.
  - Simplified `stopHighlightAnimation(card)` to strictly remove the `.highlighted` class and clear the active timer. It never wipes or re-renders the DOM.
  - Added inner dropdown preservation to `renderRaids`: captures `details.details-dropdown[open]` and `details.schedule-dropdown[open]` so any future re-renders preserve inner dropdown open states.
