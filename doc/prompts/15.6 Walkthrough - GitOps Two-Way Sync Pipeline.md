# Walkthrough: 15.6 GitOps Two-Way Synchronization Pipeline

## Overview of Changes

1. **Two-Way Synchronization Pipeline (GitOps <-> Supabase Database)**:
   - **Direction 1: Git Push -> Supabase Database**:
     - Built [`.github/scripts/sync-git-to-supabase.js`](file:///d:/GitHub/[oU1TS]/events/.github/scripts/sync-git-to-supabase.js).
     - Integrated into [`.github/workflows/notify.yml`](file:///d:/GitHub/[oU1TS]/events/.github/workflows/notify.yml). Whenever a commit touches `raids.json` on `main`, the workflow executes `sync-git-to-supabase.js`, upserting all committed raids into Supabase so the database is always 100% current with git.
   - **Direction 2: Supabase Dashboard Approval -> Git Repository (`raids.json`)**:
     - Built [`.github/scripts/sync-supabase-to-git.js`](file:///d:/GitHub/[oU1TS]/events/.github/scripts/sync-supabase-to-git.js).
     - Created [`.github/workflows/sync-database-raids.yml`](file:///d:/GitHub/[oU1TS]/events/.github/workflows/sync-database-raids.yml).
     - Triggered automatically via:
       - **Supabase Database Webhook**: Triggered when `event_submissions` updates with `status = 'approved'`.
       - **GitHub Dispatch Event**: `repository_dispatch: types: [sync_raids_from_db]`.
       - **Manual One-Click Run**: `workflow_dispatch` in the GitHub Actions tab.
       - **Automated Fallback**: Scheduled cron every 6 hours.
     - Merges approved submissions from Supabase into `raids.json`, standardizes keys, updates `tracker.json` and `feed.xml`, and automatically commits back to GitHub `main` with `[skip ci]`.
     - When maintainers run `git pull` locally, `localhost` is immediately updated!

2. **Canonical JSON Key Order Normalization**:

     `Raid_Num`, `title`, `Status`, `Type`, `dateRange`, `startDate`, `endDate`, `RegEndDate`, `venue`, `fee`, `details`, `subEvents`, `links`, `OutsideDhaka`, `IsOnline`, `city`.

3. **Date Safety Guard for "TBA" Deadlines**:
