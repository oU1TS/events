# Implementation Plan: Raid Card Deep Link Highlighting & Retraction Fix

Deep links copied from raid cards (e.g., `#raid-5`) currently navigate to the card, begin highlighting and opening, but glitch halfway through (~500ms in) and retract to the default collapsed state. This plan resolves the issue by eliminating duplicate asynchronous re-renders and preserving card open/highlight states across renders.

## User Review Required

> [!IMPORTANT]
> No breaking changes to existing data structures or CSS theme variables. All existing hash URLs (`#raid-<num>`) and copy button behaviors remain 100% backward compatible.

## Proposed Changes

### Component: Application Logic (`app.js`)

#### 1. Eliminate Redundant Background Re-renders in `syncAuthState`
- In `syncAuthState(session)`:
  - Currently, `filterAndRenderRaids()` is called unconditionally on every initial session check (`supabase.auth.getSession()` and `auth.onAuthStateChange`), even when the visitor is unauthenticated and `currentUserRole` remains `'user'`.
  - Fix: Check whether `currentUserRole` or `currentSessionUser` has actually changed before invoking `filterAndRenderRaids()`.

#### 2. Preserve Accordion Open State & Active Highlights in `renderRaids`
- In `renderRaids(raids)`:
  - Capture IDs of currently expanded cards: `currentlyOpenCardIds = new Set(Array.from(raidsContainer.querySelectorAll('details.parent-raid-card[open]')).map(el => el.id))`
  - Capture active highlighted card ID.
  - When instantiating `<details class="raid-card parent-raid-card">`:
    - Mark `card.open = true` if `currentlyOpenCardIds.has(card.id)`, or if `pendingRaidScroll === raid.Raid_Num`, or if `window.location.hash === '#raid-' + raid.Raid_Num`.
    - If this card was highlighted, retain the `.highlighted` state so animations are not abruptly aborted.

#### 3. Optimize Route Page Target Handling
- In `routePage()`:
  - When `#raid-<num>` is present and cards are already in the DOM, do not wipe and re-render `raidsContainer` if the card is already present and visible. Directly invoke `scrollToRaid(targetRaidNum)`.
  - If the target raid is a past raid and `showPastRaids` is currently `false`, toggle `showPastRaids = true` and update UI before rendering.

#### 4. Stabilize `scrollToRaid`
- Add debounce timer `activeRaidScrollTimeout` to prevent overlapping invocation.
- Ensure `<details>` opens immediately (`card.open = true`).
- Center smoothly via `card.scrollIntoView({ behavior: 'smooth', block: 'center' })`.
- Cleanly reset and re-apply `.highlighted` with forced reflow (`void card.offsetWidth`) and a fallback timeout (2200ms) alongside `animationend`.
