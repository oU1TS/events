### AI Response

I have resolved the issue causing the highlight animation to flicker or restart mid-glow when landing on raid card links.

#### 1. Why Did the Flicker Occur?
1. **False-Positive Database Re-Renders**: When `syncApprovedSubmissionsFromDatabase()` returned approved records from Supabase, `applyApprovedSubmissionsToDataset()` unconditionally flagged `hasChanges = true` even when the data matched what was already rendered. This triggered `filterAndRenderRaids()` ~250ms into the page load, clearing `raidsContainer.innerHTML = ''` and recreating the card mid-animation.
2. **Double Animation Trigger in `scrollToRaid()`**: Repeated calls were removing `.highlighted`, forcing a reflow (`void card.offsetWidth`), and restarting frame 0.
3. **CSS Transition vs Keyframe Competition**: The 0.3s CSS `transition` on `.raid-card` competed with `@keyframes highlightPulse` on `transform`, `border-color`, and `box-shadow`.

#### 2. Key Fixes Applied:
- **Deep Equality Comparison (`app.js`)**: Updated `applyApprovedSubmissionsToDataset()` to compare JSON representations. If incoming data matches existing records, `hasChanges` remains `false` and no DOM wipe occurs.
- **Idempotent Highlight Pulse (`app.js`)**: In `scrollToRaid()`, if the target card is already highlighted and actively running its pulse countdown, subsequent calls will not interrupt or restart the animation.
- **Hardware GPU Compositing (`style.css`)**: Added `transition: none !important;`, `will-change: transform, box-shadow;`, and `backface-visibility: hidden;` to `.raid-card.highlighted`.

#### 3. Regarding Your Browser Console Messages:
- `Error with Permissions-Policy header: ...`: Harmless Chromium/Blink warnings resulting from Privacy Sandbox headers injected by hosting providers or ad scripts.
- `GET ... OneSignalSDK.page.js net::ERR_BLOCKED_BY_CLIENT`: Occurs when an ad-blocker blocks the OneSignal push notification library. The portal handles this safely with no functional impact.
