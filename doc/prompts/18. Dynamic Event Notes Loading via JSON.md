## Turn 11: Copy Button Visibility On Collapsed Cards & Highlight Dropdown Restriction Fix

### User Request
now the issue of the animation highlight restricting dropdown features for raid cards still persist. also .copy-raid-link-btn used to be shown on top of the raid cards, and now it shows only when the cards are expanded. Please fix it.

### Thinking Process
1. **Analyze Why `.copy-raid-link-btn` Only Appeared When Expanded**:
   - In Turn 10, to eliminate the disallowed `<button>` inside `<summary>`, `.copy-raid-link-btn` was appended directly to `card` (`card.appendChild(copyBtn)`).
   - In standard HTML5, a `<details>` element hides all non-`<summary>` descendants when collapsed (`[open]` attribute not present).
   - Therefore, the copy link button was automatically concealed whenever the card was closed!
   - Fix:
     - Wrap each card in a `.raid-card-wrapper` div (`position: relative; overflow: visible;`).
     - Append `card` (`details.parent-raid-card`) and `copyBtn` (`.copy-raid-link-btn`) as siblings inside `cardWrapper`.
     - In `style.css`, position `.copy-raid-link-btn` at `position: absolute; top: -10px; right: -10px; z-index: 20;`.
     - This guarantees the copy link button is permanently visible on top of the card header in both collapsed and expanded states, while remaining 100% outside `<summary>`.
2. **Analyze Why Animation Highlight Restricted Dropdown Features**:
   - `filterAndRenderRaids` previously contained an artificial DOM lock:
     ```javascript
     if (!options.forceImmediate && raidsContainer && raidsContainer.querySelector('.raid-card.highlighted')) {
         pendingReRender = () => filterAndRenderRaids({ forceImmediate: true });
         return;
     }
     ```
   - When the user selected a category from the Event Type dropdown filter, `filterAndRenderRaids()` was blocked until the animation completed.
   - When the user clicked to collapse the card, `stopHighlightAnimation` fired `pendingReRender()`, which called `renderRaids()`. Since the card was still technically open when `renderRaids` ran, `openCardIds` captured it as open and re-opened it, reverting the user's collapse.
   - When the animation ended naturally, `pendingReRender()` wiped `raidsContainer.innerHTML = ''`, which snapped any open inner Details dropdown shut.
   - Fix:
     - Removed `pendingReRender` and the lock inside `filterAndRenderRaids`. Category filters and Past Raids toggles now execute immediately.
     - Simplified `stopHighlightAnimation(card)` to strictly remove the `.highlighted` class and clear the active timer. It never wipes or re-renders the DOM.
     - Added inner dropdown preservation to `renderRaids`: captures `details.details-dropdown[open]` and `details.schedule-dropdown[open]` so any future re-renders preserve inner dropdown open states.
