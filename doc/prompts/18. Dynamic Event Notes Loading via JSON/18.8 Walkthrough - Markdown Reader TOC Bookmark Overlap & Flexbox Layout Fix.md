# Walkthrough - Markdown Reader TOC Bookmark Overlap & Flexbox Layout Fix

This walkthrough details the diagnosis and resolution of the rendering glitch in `render.html` where navigation table of contents items ("bookmarks") were vertically squeezed and overlapping each other.

---

## 1. Problem Diagnosis

### The Squeezed & Overlapping Bookmarks Glitch
When viewing markdown documents with extensive headings (e.g. `event_trackers_directory.md`, `phoenix-summit-2026.md`, `competitions.md`, or `numo26.md`) inside the reader (`render.html`):
1. **Flexbox Shrink Collapsing**:
   - The navigation drawer `#nav-pane` contained `#toc-list` (`display: flex; flex-direction: column; flex: 1; overflow-y: auto; gap: 0.5rem;`).
   - Each `.toc-link` element lacked an explicit `flex-shrink: 0` declaration (defaulting to `flex-shrink: 1`).
   - Because `.toc-link` has `overflow: hidden; text-overflow: ellipsis; white-space: nowrap;`, its automatic minimum height (`min-height: auto`) resolved to `0` under CSS Flexible Box Layout specification.
   - When the document contained dozens of headings exceeding the viewport height (`100vh - 56px`), flexbox forcibly compressed each `.toc-link`'s height from ~35px down to as little as ~12px.
   - Because font size (0.9rem / 14.4px) and line height (~19px) exceeded the shrunken box height (12.78px), the text and padding overflowed each link item's boundary box, causing the bottom bookmark links to be drawn directly on top of the ones above them.
2. **Container Minimum Height Limitation**:
   - In flex columns, a child without `min-height: 0` can experience erratic scroll container overflow calculations depending on the browser engine.
3. **Main Reader Flex Protection**:
   - `.viewer-container` had `flex: 1` (`flex: 1 1 0%`) inside `body` (`display: flex; flex-direction: column; min-height: 100vh;`), leaving it vulnerable to vertical compression if any parent or viewport constraints were applied.
4. **Markdown Formatting**:
   - `doc/notes/MarXcellence-2026.md` contained extraneous leading spaces on section headers (` ## Workshop-1`, ` ## Case`, ` ## References`) and lists, causing irregular block spacing.

---

## 2. Changes Implemented

### A. TOC Navigation Pane & Bookmark Link Hardening (`css/render.css`)
- Added `min-height: 0;` to `#toc-list` to ensure the flex child correctly sizes within `#nav-pane` and delegates overflow to native smooth vertical scrolling.
- Hardened `.toc-link`:
  - Added `flex-shrink: 0;` so items **never** shrink vertically under flexbox pressure.
  - Added `min-height: 2.2rem;` and `box-sizing: border-box;` guaranteeing a comfortable, consistent ~35px touch/click target for each outline heading.
  - Added `display: flex; align-items: center;` to cleanly center link text vertically within the box.
- Added explicit styling for fourth-level headings (`.toc-link.h4`) with `padding-left: 3rem; font-size: 0.75rem; color: var(--text-muted);`.

```css
#toc-list {
    flex: 1;
    overflow-y: auto;
    padding: 1.5rem;
    display: flex;
    flex-direction: column;
    gap: 0.5rem;
    min-height: 0;
}

.toc-link {
    font-size: 0.9rem;
    color: var(--text-secondary);
    text-decoration: none;
    padding: 0.4rem 0.75rem;
    border-radius: 6px;
    transition: all 0.2s ease;
    white-space: nowrap;
    overflow: hidden;
    text-overflow: ellipsis;
    flex-shrink: 0;
    min-height: 2.2rem;
    display: flex;
    align-items: center;
    box-sizing: border-box;
}

.toc-link.h1 { font-weight: 700; padding-left: 0.75rem; }
.toc-link.h2 { padding-left: 1.5rem; font-size: 0.85rem; }
.toc-link.h3 { padding-left: 2.25rem; font-size: 0.8rem; color: var(--text-muted); }
.toc-link.h4 { padding-left: 3rem; font-size: 0.75rem; color: var(--text-muted); }
```

### B. Reader Layout Container Protection (`css/render.css`)
- Upgraded `.viewer-container` from `flex: 1;` to `flex: 1 0 auto; box-sizing: border-box;` to guarantee the reader content column never shrinks under body flex column constraints.
- Added `flex-shrink: 0;` to `.search-result-item` inside `#search-container` to safeguard against vertical compression in long search match lists.

```css
.viewer-container {
    max-width: 900px;
    width: 100%;
    margin: 0 auto;
    padding: 3rem 2rem;
    flex: 1 0 auto;
    box-sizing: border-box;
}

.search-result-item {
    padding: 0.75rem 1rem;
    cursor: pointer;
    font-size: 0.85rem;
    line-height: 1.4;
    transition: background-color 0.2s;
    border-bottom: 1px solid var(--border-color);
    flex-shrink: 0;
}
```

### C. Markdown Syntax Normalization (`doc/notes/MarXcellence-2026.md`)
- Stripped extraneous leading spaces before section dividers, headers, case files, and references.
- Converted all sections into standard CommonMark/GFM blocks for clean, predictable parsing and outline generation.
