# Implementation Plan: 15.5 GitOps Two-Way Synchronization Pipeline

Configure a robust bidirectional synchronization pipeline connecting the GitHub repository (`raids.json`) and the Supabase database (`event_submissions`), establish canonical key order formatting, fix "TBA" date safety, and incorporate Raid #22.

---

## Proposed Changes

### 1. Two-Way Synchronization Architecture (GitOps & Supabase)
- **Problem**: When updates occur in Supabase via the Review Dashboard, they remain in the database and do not automatically commit back to `raids.json` in the Git repository, leaving local development (`localhost`) desynchronized until manual download/commit. Conversely, manual Git commits to `raids.json` do not automatically seed Supabase.
- **Solution**:
  - **Direction 1 (Git -> Supabase)**: Create `.github/scripts/sync-git-to-supabase.js` and integrate into `.github/workflows/notify.yml` (or dedicated sync job). On `push` to `raids.json`, it queries Supabase and upserts approved records so the database is always 100% current with git commits.
  - **Direction 2 (Supabase -> Git)**: Create `.github/scripts/sync-supabase-to-git.js` and workflow `.github/workflows/sync-database-raids.yml`. Supports `schedule` (cron), `workflow_dispatch` (manual run), and `repository_dispatch` (webhook). It queries Supabase for approved proposals, merges them into `raids.json` in canonical key order, increments `tracker.json`, updates `feed.xml`, and commits changes back to GitHub `main`.
  - Provide complete Supabase Database Webhook setup instructions so approving an event in the dashboard triggers the GitHub Actions workflow automatically.

### 2. Canonical JSON Key Order Normalization
- **File**: [`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js)
- **Problem**: In `temp/raids (2).json`, newly approved raids displayed properties in arbitrary order (`fee`, `Type`, `city`, `links` ahead of `Raid_Num` and `title`).
- **Solution**:
  - Implement `normalizeRaidKeyOrder(raid)` enforcing canonical ordering: `Raid_Num`, `title`, `Status`, `Type`, `dateRange`, `startDate`, `endDate`, `RegEndDate`, `venue`, `fee`, `details`, `subEvents`, `links`, `OutsideDhaka`, `IsOnline`, `city`.
  - Wire `normalizeRaidKeyOrder` into `generateUpdatedRaidsJson()` so downloads and exports are always cleanly structured.

### 3. Date Handling Guard for "TBA" Deadlines
- **File**: [`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js)
- **Problem**: When `RegEndDate` is `"TBA"` (as in Raid 22), passing `"TBA"` to `new Date()` results in `Invalid Date`.
- **Solution**:
  - Add date validation guard in `app.js` ensuring `!isNaN(regDate.getTime())` before checking `today > regDate`, gracefully rendering `"TBA"` without console errors.
