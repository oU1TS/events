# Walkthrough: Raid Card Deep Link Highlighting & Retraction Fix

Resolved the issue where accessing a direct raid URL copied from a raid card (e.g., `#raid-5`) resulted in a flicker and mid-pulse glitch, followed by the card prematurely collapsing back to the default closed view. In addition, extended the highlight glow animation duration for a much more visible, smoother visual presence.

## Changes Made

### 1. Highlight Animation Duration & Keyframes (`style.css`)
- Extended the pulse animation duration from **2.0s** to **3.5s** with a smoother bezier curve (`cubic-bezier(0.22, 1, 0.36, 1)`).
- Re-engineered `@keyframes highlightPulse` with progressive multi-stage decay:
  - **0%**: Starts initial sharp accent border & subtle glow (`scale(1.01)`).
  - **20%**: Peaks at prominent accent glow (`38px` blur, `14px` spread, `rgba(var(--accent-rgb), 0.65)`).
  - **55%**: Sustained gentle glow (`26px` blur, `9px` spread, `scale(1.008)`).
  - **80%**: Soft ambient decay (`14px` blur, `4px` spread).
  - **100%**: Graceful fade back to the standard resting card shadow & border.

### 2. Application Logic (`app.js`)

#### A. Guarded Background Auth Re-Renders
- In `syncAuthState(session)`:
  - Added change detection comparing `prevRole` and `prevUserId` against the resolved credentials.
  - Prevented unnecessary calls to `filterAndRenderRaids()` when `session` resolves to `null` on visitor page loads, stopping initial background auth checks from wiping the DOM.

#### B. Accordion & Active Highlight Retention
- In `renderRaids(raids)`:
  - Captured currently opened card IDs (`details.parent-raid-card[open]`) before clearing `raidsContainer`.
  - Automatically marked cards as `open = true` if they were previously expanded, if they match `pendingRaidScroll`, or if they match the active `window.location.hash`.
  - Restored any active `.highlighted` pulse animation so that if a card is re-rendered during an animation cycle, the highlight isn't lost.

#### C. Smart Routing & Animation Reflow
- In `routePage()`:
  - If target raid cards are already present in the DOM and visible, `routePage()` now directly calls `scrollToRaid(targetRaidNum)` instead of tearing down the grid.
  - Automatically activates `showPastRaids = true` and updates toggle controls if targeting a past raid.
- In `scrollToRaid(raidNum)`:
  - Added debounce timer `activeRaidScrollTimeout` (120ms) to ensure clean single-shot executions.
  - Expanded `<details>` card immediately (`card.open = true`).
  - Added forced reflow (`void card.offsetWidth`) before applying `.highlighted` so that repeated clicks on the same link restart the animation cleanly.
  - Updated fallback timeout to **3800ms** (synchronized with the 3.5s animation duration + safety buffer).
