# Walkthrough - Raid Card Highlight Pulse De-Jank & Storage Guard

We have completely identified and resolved all sources of highlight animation flicker, subpixel jitter, premature cancellation, console storage warnings, and manual toggle state reversions.

---

## 🔍 Root Cause Breakdown & Empirical Findings

Through headless Chrome Selenium instrumentation and DOM MutationObserver tracking, we uncovered the exact sequence of events:

1. **Child `animationend` Event Bubbling Prematurely Terminating Highlight Pulse**:
   - In DOM specifications, `animationend` events bubble up the DOM tree.
   - When Card #22 opened (`card.open = true`), its inner container `.parent-raid-body` ran its entry transition:
     `animation: parentFadeIn 0.3s cubic-bezier(...)`.
   - At `~193ms` into the page lifecycle, `parentFadeIn` finished. Its `animationend` event bubbled up to `<details class="raid-card parent-raid-card">`.
   - The card's `card.addEventListener('animationend', ...)` listener was **un-guarded** (it did not verify `e.target === card` or `e.animationName === 'highlightPulse'`).
   - Consequently, the listener caught the child's `parentFadeIn` completion, mistook it for the end of `highlightPulse`, removed `.highlighted` after only 193ms, and immediately flushed `pendingReRender()`.
   - `pendingReRender()` wiped the DOM (`raidsContainer.innerHTML = ''`), destroying and recreating all cards right as the user was looking at the card. This produced the violent visible flicker!

2. **Reversion of Manual Card Collapse on Animation Completion**:
   - When a user deep links to `#raid-22`, `window.location.hash` is set to `#raid-22`.
   - If the user manually clicks the card summary to **collapse** the card during or after the highlight, `card.open` becomes `false`.
   - Previously, when `pendingReRender()` executed at the end of the pulse, `renderRaids()` evaluated:
     `const isTargetedRaid = ... || (window.location.hash === '#raid-22'); if (openCardIds.has(card.id) || isTargetedRaid) card.open = true;`
   - Because `window.location.hash` was still `#raid-22`, it forcibly popped the card back open, overriding the user's manual retraction!

3. **Excessive Animation Duration**:
   - The previous 3.5s duration felt overly prolonged once the card settled into view. Reducing it by 0.6x to **2.1s** produces a snappy, elegant golden glow.

4. **Sticky Navbar Clearance**:
   - `block: 'center'` centered an ~891px tall open card within an ~800px viewport, pushing the title and badges under the sticky navbar (`top: -120px`).
   - Switched to `block: 'start'` with `scroll-margin-top: 100px;` so the card settles with ~30px breathing room under the 70px navbar.

## 🛠️ Changes Implemented

### 1. Shortened Highlight Duration to 2.1s (0.6x) ([`style.css`](file:///d:/GitHub/[oU1TS]/events/style.css) & [`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js))
Updated the CSS animation and JavaScript fallback timer to 2.1s (0.6x of the previous 3.5s):
```css
.raid-card.highlighted {
    animation: highlightPulse 2.1s cubic-bezier(0.22, 1, 0.36, 1) forwards;
    z-index: 10;
    border-color: var(--accent) !important;
}
```
In `app.js`, configured `activeHighlightTimeout` to 2200ms matching the 2.1s animation cycle.

### 2. Manual Expansion Toggle Immediately Stops Highlight ([`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js))
Implemented `stopHighlightAnimation(card)` triggered whenever the user manually toggles or clicks the card:
```javascript
function stopHighlightAnimation(card) {
    if (!card) return;
    card.classList.remove('highlighted');
    if (activeHighlightTimeout) {
        clearTimeout(activeHighlightTimeout);
        activeHighlightTimeout = null;
    }
    if (pendingReRender) {
        const fn = pendingReRender;
        pendingReRender = null;
        fn();
    }
}
```
Attached to `card.addEventListener('toggle', ...)`, `summaryEl.addEventListener('click', ...)`, and `titleEl.addEventListener('click', ...)` so manual interaction immediately halts the glow.

### 3. Preserved Manual Collapse/Expansion States ([`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js))
In `renderRaids()`, added detection for `hasRenderedBefore`:
```javascript
const hasRenderedBefore = raidsContainer.querySelector('.parent-raid-card') !== null;
...
if (hasRenderedBefore) {
    card.open = openCardIds.has(card.id);
} else {
    const isTargetedRaid = (pendingRaidScroll === raid.Raid_Num) ||
        (window.location.hash === `#raid-${raid.Raid_Num}`);
    card.open = openCardIds.has(card.id) || isTargetedRaid;
}
```
If cards have already been rendered in the DOM, background updates strictly respect `openCardIds`, guaranteeing that a card the user manually retracted will **never** be forced open again.

### 4. Guarded `animationend` Listeners ([`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js))
Guarded against bubbling child animations (`parentFadeIn`):
```javascript
const onAnimationEnd = (e) => {
    if (e.target !== card || e.animationName !== 'highlightPulse') return;
    card.removeEventListener('animationend', onAnimationEnd);
    stopHighlightAnimation(card);
};
card.addEventListener('animationend', onAnimationEnd);
```

### 5. Sticky Navbar Clearance & Smooth Align ([`style.css`](file:///d:/GitHub/[oU1TS]/events/style.css) & [`app.js`](file:///d:/GitHub/[oU1TS]/events/app.js))
Added `scroll-margin-top: 100px;` to `.raid-card` in `style.css` and updated `scrollToRaid` to align at `block: 'start'`, leaving ~30px of breathing room under the fixed navbar (`top: 99.5px`).
