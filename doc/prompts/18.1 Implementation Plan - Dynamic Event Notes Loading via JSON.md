# Implementation Plan - Dynamic Event Notes Loading via notes.json

## Overview
Currently, the Event Notes section in `index.html` (`#notes-container` around line 356) derives its list by filtering `pastRaidsData` from `raids.json` for raids with a `links.notes` field. This prevents standalone notes, directories, and guides located in `doc/notes` (such as `competitions.md` and `event_trackers_directory.md`) from being surfaced independently.

This implementation plan transitions `#notes-container` to load from a dedicated, structured `notes.json` data file located at the repository root, mirroring the asynchronous loading, caching, skeleton loaders, and download export architecture of `raids.json`.

---

## User Review Required

> [!NOTE]
> No breaking changes or invasive architectural modifications are required. `notes.json` will serve as the primary source of truth for notes, while `app.js` will maintain backwards-compatibility by cross-referencing any custom `links.notes` from `raids.json` or approved submissions.

---

## Proposed Changes

### 1. Data Layer: Create `notes.json`
Create `notes.json` at the root directory containing structured entries for all markdown documents currently housed in `doc/notes/`:
- `doc/notes/phoenix-summit-2026.md` (Raid #1: Phoenix Summit 2026)
- `doc/notes/amd-dev-hackathon-2026.md` (Raid #2: AMD Developer Hackathon: ACT II)
- `doc/notes/MarXcellence-2026.md` (Raid #3: NSU MarXcellence 2026)
- `doc/notes/competitions.md` (Undergraduate CSE Competitions Directory)
- `doc/notes/event_trackers_directory.md` (Event Trackers & Dev Competitions Master Directory)

**Schema Definition**:
```json
{
  "id": "phoenix-summit-2026",
  "title": "Phoenix Summit 2026 Delegation Notes",
  "category": "Conference Notes",
  "description": "UITS Event Raiders delegation notes, safety guidelines, industry senior advice (Rezwan bhai), and technical session highlights.",
  "file": "doc/notes/phoenix-summit-2026.md",
  "raidNum": 1,
  "tags": ["cybersecurity", "blue-team", "red-team", "wazuh", "delegation-notes"],
  "lastUpdated": "2026-06-27"
}
```

### 2. Markup: `index.html`
- Inside `#notes` (`index.html:L347-L360`):
  - Add an action bar matching `#raids`: includes a "Download notes.json" button (`#download-notes-json-section-btn`).
  - Update `#notes-container` to include skeleton loader placeholder elements while data is asynchronously fetched:
    ```html
    <div id="notes-container" class="resources-grid">
        <div class="resource-card skeleton"></div>
        <div class="resource-card skeleton"></div>
        <div class="resource-card skeleton"></div>
    </div>
    ```

### 3. Application Logic: `app.js`
- **State Management**:
  - Add `let eventNotesData = null;` and `let isNotesLoading = false;`.
- **Asynchronous Data Loading**:
  - Implement `async function loadEventNotes(options = {})` fetching `notes.json` (with cache bypass option `forceFresh`).
  - Fallback and error handling with user-friendly notices.
- **Card Rendering (`renderEventNotes`)**:
  - Render cards dynamically into `#notes-container` using the loaded notes.
  - Display category badges, raid number tags (`Raid #N`), title, descriptive summary, and tag pills.
  - Render action links:
    - `render.html?file=${encodeURIComponent(note.file)}` ("View Notes" with markdown document icon).
    - `#raid-${note.raidNum}` ("View Campaign" with arrow icon, displayed when `raidNum` exists).
  - Cross-reference with `pastRaidsData` to ensure any raid with a notes link that is not yet in `notes.json` is safely surfaced without duplicates.
- **Export Utility**:
  - Implement `downloadNotesJsonFile()` bound to `#download-notes-json-section-btn`.
- **Routing & Bootstrap**:
  - Trigger `loadEventNotes()` on startup (alongside `loadPastRaids()`) and whenever navigating to `#notes`.

### 4. Styling Polish: `style.css`

- Style note badges, tag pills, and action links within the note cards.
